# 参考项目压缩笔记

这份文档把工作区里的大型参考项目压缩成对 `AIColonyDemo` 有用的设计与实现方向。原则是只吸收机制和结构，不直接搬运参考项目源码。

## 当前项目定位

`AIColonyDemo` 是一个俯视角小型殖民模拟：玩家用中文自然语言下令，殖民者执行采集、建造、制作、撤退和战斗，夜晚有逐步增强的袭击压力。

后续扩展时，优先围绕三个目标：

- 指令更好懂：中文命令能稳定转成动作。
- 世界更像活的：资源、夜晚、袭击、基地防御有因果关系。
- 模块更好改：新增资源、建筑、敌人、工具时少碰主循环。

## game 参考压缩

`game` 主要可作为殖民模拟设计参考。对本项目有价值的是系统思路，不是文件体量。

可借鉴功能：

- 工作任务：把“砍树、采矿、搬运、建造、制作、攻击”都看成任务，任务有目标、距离、耗时、失败条件和完成回报。
- 任务中断：敌人接近、资源消失、道路堵住、角色受伤时，任务应该能取消或重选。
- 事件压力：夜袭、疾病、缺粮、建筑损坏都可以成为“事件”，由时间线或难度曲线触发。
- 数据定义：物品、建筑、敌人、事件最好从表读取，脚本只负责执行逻辑。
- 殖民者差异：每个角色可以有技能倾向，例如伐木、采矿、建造、战斗、医疗。

适合落地到 Godot 的模块：

- `scripts/core/task_queue.gd`：统一排队和分配任务。
- `scripts/core/event_director.gd`：按天数、资源、防御状态生成事件。
- `data/defs/*.json`：物品、建筑、敌人、事件的轻量数据表。
- `scripts/entities/colonist_stats.gd`：角色技能、心情、受伤、疲劳。

暂不建议实现：

- 复杂情绪、社交、派系、全地图模拟。这些会快速膨胀，不适合当前 Demo 阶段。

## Terraria-Source-Code-master 参考压缩

这个目录可作为 2D 沙盒世界的功能索引。当前项目不是横版挖矿游戏，因此只提炼可复用思想。

可借鉴功能：

- 方块世界：把地形、资源、墙、建筑都统一为格子数据，减少特殊判断。
- 世界生成：用随机种子生成森林、矿点、空地、水域等区域，让每局有差异。
- 物品/配方：工具和建筑都走统一的材料消耗与产出。
- 敌人生成：敌人出生点、时间、周围环境、玩家基地状态共同决定出现概率。
- 反馈文字：采集、受伤、制作完成时弹出短提示，让玩家知道命令结果。

适合落地到 Godot 的模块：

- `scripts/core/world_generator.gd`：按种子生成树、石头、铁矿、空地、水边。
- `scripts/core/recipe_book.gd`：维护工具和建筑配方。
- `scripts/core/spawn_rules.gd`：夜袭和特殊敌人的生成条件。
- `scripts/ui/floating_text.gd`：小型战斗/采集数字提示。

近期最划算的改进：

- 给现有世界加入“矿脉/树林/废墟”三种区域，而不是完全随机撒点。
- 给夜袭增加“从地图边缘靠近基地”的方向感。

## tModLoader-1.4.5 参考压缩

这个目录最有价值的是插件式内容组织思路。它提示我们：如果以后要让游戏容易扩展，内容应该通过稳定接口接入。

可借鉴功能：

- Loader 思维：新增敌人、建筑、物品时，不改主循环，只注册定义和回调。
- Hook 思维：在“任务开始、任务完成、受击、死亡、夜晚开始、建筑放置”这些节点开放扩展点。
- ExampleMod 思维：给每类内容留一个最小示例，方便以后照着加新内容。
- 配方分组：类似“任意木材”“任意矿石”的材料组，能让中文命令更自然。

适合落地到 Godot 的模块：

- `scripts/core/content_registry.gd`：注册资源、建筑、敌人、配方。
- `scripts/core/game_hooks.gd`：集中触发可选回调。
- `data/examples/`：保留最小可改示例。

暂不建议实现：

- 完整 Mod API、热加载、外部脚本沙盒。现在先把内部数据化做好即可。

## TerrariaClone-main 参考压缩

这个项目本身更像反面教材，但仍有一些能提炼的点。

可借鉴功能：

- 简单库存：物品堆叠、添加、移除、快捷栏选择。
- 掉落物：敌人和资源都可以掉落物品，再由角色拾取。
- 区块概念：地图可以分块更新，减少每帧遍历全图。
- 光照/电路可以以后做，但当前项目不需要。

重要教训：

- 不要把所有玩法塞进一个巨大脚本。
- 不要用魔法数字表示资源、建筑、敌人。
- 数据表要有名字、说明、默认值，便于策划改。

适合落地到 Godot 的模块：

- `scripts/core/inventory.gd`：统一管理资源和物品堆叠。
- `scripts/entities/dropped_item.gd`：世界掉落物。
- `scripts/core/world_chunks.gd`：地图扩大后再做分块更新。

## 对 AIColonyDemo 的优先级建议

优先级 1：

- 把资源、建筑、工具、敌人的硬编码数据迁入 `data/defs/`。
- 增加 `task_queue.gd`，让多个命令可以排队，不会互相覆盖。
- 增加 `recipe_book.gd`，让制作逻辑从主循环分离。

优先级 2：

- 增加世界生成区域：树林、矿区、水边、废墟。
- 增加角色技能：伐木、采矿、建造、战斗。
- 增加浮动反馈文字。

优先级 3：

- 增加事件导演：按天数与基地强度调整夜袭。
- 增加更多建筑：门、篝火、储物箱、陷阱、瞭望塔。
- 增加更丰富的中文命令模板。
