# 03 · AI 对话与动作表

## 1. 对话者：AI 总管

玩家每次发言，AI 总管收到三段输入：

1. **系统提示词**（固定）：角色设定 + 动作表 schema + 铁律
2. **世界快照**（每回合重算）：时间、天数、库存、小人列表与数值、威胁、当前任务队列
3. **玩家输入**：原始中文

输出必须是**一个 JSON 对象**，其中 `speech` 用于聊天框显示，`actions` 用于驱动游戏。

## 2. 输出格式（唯一契约）

```json
{
  "speech": "行，先砍树。李铁柱、王二丫去东边林子，天黑前我得看到三张床。",
  "actions": [
    { "type": "chop_tree", "count": 12, "target": "nearest", "assignee": "any" },
    { "type": "build_bed",  "count": 3,  "target": "base",    "assignee": "any" }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `speech` | 是 | 给玩家看的话，中文，有性格，允许吐槽 |
| `actions` | 是 | 数组，可为空 `[]` |
| `type` | 是 | 动作 id，必须来自动作表 |
| `count` | 否 | 执行次数，默认 1，上限 99 |
| `target` | 否 | `nearest` / `base` / `any` / 具体坐标 `[x,y]`，默认 `nearest` |
| `assignee` | 否 | `any` / 小人名字，默认 `any`（谁空谁去） |

## 3. 系统提示词要点（铁律）

- 只输出 JSON，不要 markdown 代码块，不要解释
- 动作 `type` **必须**是动作表里存在的 id，编造的动作会被丢弃
- 一次最多 6 个动作，按优先级排序
- 玩家问情况 → `actions` 留空，`speech` 详细回答
- 资源不够时，先排采集动作，再排建造动作
- 夜晚来袭前，主动提醒并优先排防御动作
- 语气：干练的工地总管，短句，偶尔吐槽，不谄媚

## 4. 兜底规则解析

无 Key / 超时 / JSON 解析失败时启用。按关键词表扫描玩家输入，命中即生成对应动作。

| 关键词 | 动作 |
|---|---|
| 砍树 / 木头 / 木材 | `chop_tree` ×N |
| 挖石 / 石头 / 采石 | `mine_stone` ×N |
| 铁 / 铁矿 | `mine_iron` ×N |
| 墙 / 围墙 / 围起来 | `build_wall` ×N |
| 门 | `build_door` |
| 床 / 睡觉的地方 | `build_bed` ×N |
| 营火 / 篝火 / 火堆 | `build_campfire` |
| 火把 / 照明 | `build_torch` ×N |
| 炮塔 / 防御塔 | `build_turret` ×N |
| 农田 / 种地 / 开垦 | `build_farm_plot` ×N |
| 播种 / 种 | `plant_crop` ×N |
| 收 / 收割 / 采摘 | `harvest_crop` |
| 做饭 / 烹饪 / 吃的 | `cook_meal` ×N |
| 吃 / 吃饭 | `eat` |
| 睡 / 休息 | `sleep` |
| 巡逻 | `patrol` |
| 修 / 修理 | `repair` |
| 治疗 / 包扎 | `treat_wound` |
| 防守 / 防御 / 迎战 / 打 | `defend` |
| 集合 / 回来 / 撤退 | `regroup` |
| 停 / 取消 / 别干了 | `cancel_all` |
| 怎么样 / 情况 / 报告 | （仅语音，无动作） |

数字提取：正则抓中文/阿拉伯数字（`三` `3` `12`），无数字时用默认值。
任务名提取：命中「张三去砍树」时，把已知小人名字扫一遍，写入 `assignee`。

## 5. 动作表 schema（代码侧定义）

每个动作在 `actions.gd` 里登记为一条定义：

```gdscript
{
  "id": "chop_tree",
  "label": "砍树",
  "duration": 3.0,          # 单次耗时（秒，游戏时间）
  "range": 1.5,             # 需要靠近目标的距离（格）
  "target_kind": "tile",    # tile / entity / point / none
  "requires": {},           # 资源前置，如 {"stone": 10}
  "produces": {"wood": 3},  # 产出
  "consumes": {},           # 消耗
  "skill": "work",          # 影响的属性
  "icon_color": "#8B5A2B"
}
```

动作表是**唯一的真相来源**：AI 提示词里的动作清单由它生成，兜底解析的关键词表也挂在它上面，不会出现"提示词写了但代码没实现"的漂移。
