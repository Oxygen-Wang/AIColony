# 02 · 系统架构

## 模块划分

| 模块 | 职责 | 是否依赖 AI |
|---|---|---|
| World 世界 | 128×128 地图生成、地形渲染、相机 | 否 |
| Pawn 小人 | 数值（饥饿/疲劳/心情/血量）、移动、工作 | 否 |
| TaskSystem 任务系统 | 维护任务队列、按优先级派活给空闲小人 | 否 |
| Actions 动作表 | 20+ 动作的 id → 定义（耗时、消耗、产出、目标类型） | 否 |
| Beast 野兽 | 夜间生成、寻敌、攻击 | 否 |
| GameState 全局 | 时间、库存、天计数、胜负状态 | 否 |
| AIBridge AI 桥 | 拼提示词 → 调 DeepSeek → 解析 → 落成任务 | 是 |
| FallbackParser 规则兜底 | 关键词匹配，API 挂了也能玩 | 否 |
| UI | 聊天框、HUD、速度控制、结算 | 否 |

**核心设计原则：游戏本体不依赖 AI。** AIBridge 只是一个"输入设备"，和键盘鼠标同级。
拔掉它，用兜底解析器，Demo 依然完整可玩。

## 数据流

```
玩家输入文本
   │
   ├─→ AIBridge.build_prompt()   ← 注入快照：小人数值 / 库存 / 时间 / 威胁
   │        │
   │        ├─ HTTP ─→ DeepSeek ─→ JSON 文本
   │        │                          │
   │        └─ 失败/超时 ─→ FallbackParser.parse() ─→ 同样结构的 JSON
   │                                                │
   └──────────────→ ActionParser.validate(json) ←──┘
                          │  （非法动作直接丢弃并写日志，不崩游戏）
                          ↓
                    TaskSystem.enqueue(tasks)
                          ↓
                    空闲小人领取 → 寻路 → 执行 → 结算产出
                          ↓
                    GameState 更新 → 下一帧 UI 刷新
```

## 关键决策

### 指令转换
AI 总管输出 **JSON 动作表**，游戏只认动作表。自由文本只用于显示在聊天框里。

### 小人状态
本地数值 + 纯代码驱动衰减。AI 只读不写。

### API 容错
三级降级：

1. **正常**：DeepSeek 返回合法 JSON → 直接用
2. **半残**：返回里夹带 markdown 代码块 / 废话 → 用正则抠出第一个 `{...}` 块再解析
3. **全挂**：超时（>12s）、网络错误、解析失败 → 规则解析兜底，并在聊天框标注「⚠ 已降级为规则解析」

**Demo 永远可玩**是硬要求。

### API 接入
- Godot `HTTPRequest` 节点直调 `https://api.deepseek.com/chat/completions`
- 模型：`deepseek-flash`（可在设置里改）
- Key 来源优先级：设置面板写入 `user://config.cfg` → 项目根目录 `deepseek_key.txt` → 环境变量 `DEEPSEEK_API_KEY`
- 无 Key 时直接走兜底解析，不报错、不阻塞

### 线程模型
Godot 主线程跑游戏循环，HTTPRequest 走引擎自带异步，不阻塞帧。
请求期间聊天框显示「总管思考中…」，玩家可继续操作相机。

## 性能约束

- 128×128 地形渲染成 **单张 ImageTexture**，一次 draw call，不逐格建节点
- 野兽上限 40，小人 6，全部走 `_process` 轻量更新
- 寻路用格子 BFS，仅在目标变化时重算，不每帧算
